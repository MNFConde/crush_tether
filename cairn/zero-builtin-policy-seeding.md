# 零内置策略与默认配置生成

## 形成背景

P1 落地后判定表（READONLY/DESTRUCTIVE/GIT_* 等）以 Rust 常量写死在 engine.rs、编译进二进制。用户指出：软件本身不应提供任何规则，默认规则也必须由外部配置文件与脚本提供。经确认定稿为设计变更（非补充），推翻原「全局层 = 编译内置默认」的设定。

## 当前结论

- **二进制 = 纯引擎，零策略数据**：只实现解析/flatten/特征提取（`writes_file`/`path_escapes`/`pipe_to_shell` 等）/安全原语/管线/组合裁决；一行策略数据都不内嵌。
- **默认策略 = 外部文件**：默认 `rules.toml` + 默认 `rules.rhai`（跨参数逻辑：`find -delete/-exec` 突变、`git config` ≥2 位置参数写判定）。二进制内嵌的只是**生成模板**——生成源数据，不参与判定。
  - **更正（2026-09-05，随配置格式草案 v1）**：默认 `rules.toml` 的内容界定收窄为「无条件的纯查表」（`[local]`/`[global]` 双表三桶），原「flag 前缀、位置参数数、特征布尔」等声明层字段随条件判断下沉脚本层而取消；默认包结构以 `doc/design.md`「配置格式与脚本边界（草案 v1）」为准，待 P2/P3 验收后升格定稿。生成触发/留档/效力顺序等机制不受影响。
- **生成触发**：按层寻找（全局 → 用户 → 项目 + `--config`/`CRUSH_TETHER_CONFIG`）后**三层合并仍无任何有效配置**才在项目 `.crush-tether/` 生成；任一层有效即尊重现状（避免将来全局/用户自定义被项目层默认值遮蔽）。
- **效力顺序（用户明确）**：三层都有时，项目 > 用户 > 全局；不存在「全局默认粘性」。
- **损坏 ≠ 缺失（2026-09-06 收窄）**：文件存在但解析失败 → stderr 告警 + fail-safe confirm 兜底，**原文件不动、不留档不生成**；仅文件不存在（三层皆缺）才触发生成。
  - **更正（2026-09-06）**：原方案「先改名留档 `.bak-<时间戳>` 再生成默认」被收窄——留档接管会使 serve 冷启动遇用户手改中间态时裁决静默漂移且 `.bak` 堆积；fail-safe confirm 本身已安全可用，无需换配置恢复。论证见 `doc/decisions.md` D-03。
- **引导豁免**：生成动作本身不经规则链判定，属管线引导步骤；只写 `.crush-tether/` 固定文件名。
- **幂等与原子**：模板内容恒定 → 重复生成结果一致；temp + rename 原子替换，多 hook 并发发现缺失自然收敛。
- **fail-safe 衔接**：生成前/生成失败按既有 fail-safe（confirm），绝不放行。
- **全局/用户层生成延后**：v1 只做项目层；全局/用户默认文件由命令提供（如 `init --global`，后期设计）。
- **测试迁移**：89 条回归用例改为「引擎 + 默认规则 fixture」驱动；生成出的默认配置包本身成为验收对象；断言与定稿草案冲突时以草案为准更新用例并留变更记录（guard.py 是语义参考而非验收标准，2026-09-06 定位澄清）。
- **命令知识库不构成内置策略**（2026-09-06）：知识库（knowledge.toml / bucket）记录命令世界的通用**事实**（读写属性/别名/联系），不产生任何裁决——「curl 可能写」是事实、「curl 该 confirm」才是策略；与零内置政策并存不冲突（见 `cairn/command-knowledge-base.md`、`doc/design.md`「命令知识库」节）。

## 经验与教训

- **教训：策略藏进代码常量会固化产品语义**。P1 按原设计把判定表 1:1 平移进 engine.rs 是当时正确的验收路径（可平移、可回归），但「内置默认」本身是应被质疑的设定——引擎能力与策略数据分层后，改规则不再重编译、策略可审计可 diff、热重载（Arc 快照）全部用上。
- **教训：损坏配置的处理要以 fail-safe 为底、不动用户现场**。「直接重写默认」静默销毁手改内容（2026-09-04 已否）；「留档改名后接管」仍会静默改变裁决行为并堆积备份（2026-09-06 再否）——最终形态：告警 + confirm 兜底 + 原文件不动，生成严格限定「从零引导」场景。
- **生成触发的分层语义要显式钉死**：若按「项目层缺失即生成」，将来全局/用户层有自定义时会被项目层新生成的默认值遮蔽，且用户难以察觉；「三层皆缺才生成」把生成严格限定为从零引导场景。
